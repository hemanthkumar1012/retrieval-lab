Ask a question and see how each retriever answers it.

This searches 5,183 scientific abstracts (BEIR SciFact) stored in Postgres. Vector search finds passages with similar meaning, full-text search finds the exact words, rank fusion merges both lists, and a cross-encoder reorders the best twenty. Every stage is timed.

    What the benchmarks say

    Retrieval quality was measured on BEIR SciFact: 300 scientific claims, each with the abstracts that support or contradict it. These are the real numbers behind the settings this demo runs with, and a few of them changed the design.

    Which retriever finds the right abstracts

      Vector search is the strong retriever. The Postgres full-text stage is much weaker on its own, and the reranker adds recall rather than ranking quality. The column on the right is median latency.

      Turning down the full-text list

      With equal weights, fusing in the weak full-text list pulls hybrid search below vector search alone. Lowering its weight recovers that, so the demo runs at 0.1. The reranker makes the weight irrelevant.

        Choosing the semantic cache threshold

        A cached answer is reused when a new question is this similar to an old one. Too low and different questions get the wrong answer. Too high and nothing ever hits. Drag to see the trade-off.

          Shrinking the models

          Both models run as int8 ONNX files, so the whole API fits in one serverless function with no PyTorch.

          Chunking barely matters

          nDCG@10 for three ways of cutting abstracts into passages. The differences are about the size of run-to-run noise.
